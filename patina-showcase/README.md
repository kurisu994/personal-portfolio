# 苔痕 · PATINA

暖纸底色上，Gray-Scott 反应扩散缓慢长出苔绿与墨色的纹理：从彼此不相连的斑点起，一路长成密集圆斑、迷宫与细密分叉，最后几乎铺满整张纸；接着一圈水渍从中心洇开，把它洗回纸面，从头再来。

这个目录是工程版（React 19 + TypeScript + WebGL2 + Rsbuild）。零第三方依赖的单文件版保存在相邻的 [`../patina/index.html`](../patina/index.html)。

## 本地运行

使用 Node.js 22.12+ 和 pnpm。当前验证环境是 Node.js 24.12.0、pnpm 12.4.2。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

打开终端显示的本地地址，默认 `http://127.0.0.1:3000/`。

## 操作

- **点一下** 播种，**拖动** 涂抹，**按住不动半秒**或**按住 Shift / 右键**擦除。
- **数字键 1–5** 直接跳到某个形态族。
- **空格** 暂停，**滚轮** 调节演化速度（0.25×–3×）。
- **声音** 默认关闭，点一下开启；底层嗡鸣的厚度与音高随覆盖率变化。
- 界面右上角可以切换声音与暂停，右下角是形态族列表。

## 构建与部署

```sh
pnpm typecheck
pnpm build
pnpm preview
```

将 `dist/` 的**全部内容**上传到静态服务器即可，无需 Node.js 服务端。字体随构建自托管，运行时不依赖第三方 CDN。

支持部署在子目录，例如 `https://example.com/patina-showcase/`。访问地址需保留结尾的 `/`。

`public/og-patina.jpg` 是真实页面生成的 1200 × 630 宣传分享图（由 `pnpm make:og` 生成）。正式发布前，把 `index.html` 中 `og:image` 改成该图片的完整线上 URL，并补充实际站点的 `og:url` / canonical 地址。

## 实现

| 模块 | 职责 |
| --- | --- |
| `src/App.tsx`、`src/styles.css` | 画布挂载、渲染循环、指针与键盘交互、设备调优、调试接口 |
| `src/ui/Overlay.tsx` | 标题、形态信息、进度、诗句、形态族按钮 |
| `src/core/GrayScott.ts` | 反应扩散的 CPU 参考内核，验收脚本直接跑它 |
| `src/core/presets.ts` | 形态族参数、漫游折线、时间轴 |
| `src/core/Director.ts` | 叙事状态机：播种 → 蔓延 → 冲刷 |
| `src/core/palette.ts` | 纸墨色阶 |
| `src/core/tuning.ts` | 每帧步数与像素密度 |
| `src/gl/shaders.ts`、`src/gl/Engine.ts` | WebGL2 模拟与显示 |
| `src/audio/Soundscape.ts` | 程序化音景（低频嗡鸣、生长点音、重生水声） |
| `src/data/poems.ts` | 10 段中英短诗 |

模拟场固定为 256²，两个 32 位浮点纹理做 ping-pong，每帧推进 16 步（移动端 10 步）。显示分两趟：先把 V 场映射成纸墨色阶与边缘墨晕写进一张 8 位中间纹理，再按屏幕像素叠纸纹与暗角并放大——所以模拟纹理可以用 NEAREST 过滤，不必依赖 `OES_texture_float_linear`。

页面进入后台后暂停推进，返回时续行；持续掉帧时降低像素密度，最低到 1 倍。

## 参数是怎么定下来的

这一节记录几个踩过的坑，因为它们决定了代码的形状，改动任何一条都会让画面坏掉。

**参数不是从文献抄的。** Pearson 论文与常见开源实现的参数表各自对应不同的拉普拉斯核（五点与九点的形态区不同），直接搬过来会落在双稳态边界上。五个形态族的 (F, k) 都是本项目九点核 + 显式欧拉下实测校准的。

**校准分辨率必须与运行分辨率一致。** `(F, k)` 平面里「有图案」的只是一条窄带，而窄带位置会随网格尺寸移动。早先在 64² 上校准的 `mitosis(0.0367, 0.065)` 搬到 256² 直接死掉（覆盖率 0.000）。所以模拟分辨率固定 256²、不随设备变化，`verify:patina` 也按 256² 复核。

**漫游顺序必须按覆盖率递增。** Gray-Scott 有一个「铺满」吸引子：整场被 V 占满后 U 几乎耗尽，而反应项是 `u·v²`，没有 U 就没有燃料。此时切到任何稀疏形态，V 都会衰减到零且再也长不回来。实测从 `bloom` 的 0.854 切到 `maze`，45000 步后覆盖率 0.000。原先「茂密 → 稀疏 → 茂密」的呼吸式漫游因此会把画面洗白；现在的顺序是斑点 → 细胞分裂 → 迷宫 → 珊瑚 → 茂密，覆盖率单调上升，茂密铺满后由冲刷回到起点。这条约束由验收脚本断言，改回去会直接报错。

**参数不能瞬切。** 真实运行的 8 秒渐变是必要的，不是装饰；瞬切同样会让 V 场崩解（`maze → coral` 瞬切后 0.420 → 0.000，走渐变则是 0.420 → 0.501）。所以验收脚本也沿路径连续推进，而不是「跳到目标再跑若干步」。

**饱和阈值贴近 1。** 覆盖率会随分辨率上升（同一组参数 64² 下 0.85、256² 下 0.98），阈值定低了会让「茂密」在漫游第一段就反复触发重生，后面四个形态永远没机会出现。它现在的定位是安全阀，正常节奏下重生由「漫游走完一圈」触发。

## 验证

```sh
pnpm verify:patina                        # 纯 Node，不需要浏览器
pnpm verify:visual                        # 需要先在另一个终端跑 pnpm dev 或 pnpm preview
```

`verify:patina` 直接跑 CPU 内核，检查四类事情，报告写入 `artifacts/patina/report.json`：

- 数值健全性：五组参数五万步不发散、不越界，播种后 V 总量确实长起来。
- 长程稳定性：五万步内覆盖率始终落在图案区，不踩到双稳态边界。
- 真实分辨率复核：按 256² 再跑一次，与 `presets.ts` 登记的覆盖率对账，并断言漫游顺序确实按覆盖率递增、且「铺满后切稀疏会崩解」这条结论仍然成立。
- 叙事正确性：漫游折线每一段整段安全、参数连续；按真实步率跑完整段过渡后画面仍然活着；状态机的相位顺序、播种数量（3–8 团）、一圈时长与冲刷时长正确。

`verify:visual` 用真实 Chrome 同时验收工程版与零依赖版：无控制台错误、模拟场尺寸与浮点支持、沿路径走完五个形态并逐一截图、覆盖率必须单调不减、五个形态的平均亮度必须有实质差异，以及 390 / 1440 / 2200 / 3300 四档视口无溢出。截图与报告写入 `artifacts/visual/`。

零依赖版只验证第一个形态：它跑在 CPU 上，走完整圈要约两分钟。完整漫游、路径连续性与形态递增由工程版与 `verify:patina` 负责。

未安装 Chrome 时运行 `pnpm exec playwright install chromium`。
